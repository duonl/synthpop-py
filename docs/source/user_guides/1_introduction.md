# 1. Introduction

**synthpop-py** is a Python package for generating synthetic tabular data using sequential modelling methods. It is based on the ideas and methodology of the R package [**synthpop**](https://www.synthpop.org.uk/), while providing a modern Python interface and software architecture that is easier to learn, integrate and maintain.

The package is intended for researchers, data scientists, statisticians and practitioners who want to generate synthetic versions of tabular datasets for analysis, development or data sharing.

synthpop-py supports tabular datasets containing both numeric and non-numeric variables, including floating-point numbers, integers, booleans, strings and categorical variables. Missing values are supported throughout the synthesis process.

---

## 1.1. Synthetic data
Synthetic data is artificially generated data that resembles an original dataset without being a direct copy of it. Rather than replicating existing records, synthetic data is generated by learning the statistical relationships between variables in the original data and using these relationships to create new observations.

The goal is to produce data that is sufficiently similar to the original dataset for downstream analysis while reducing the need to share the original data. Synthetic data can be useful for exploratory analysis, software development, method development, education, and collaborative research where access to sensitive data is restricted.

Generating useful synthetic data requires balancing several objectives. A synthetic dataset should preserve the statistical properties that are important for analysis while reducing disclosure risks associated with sharing the original data.

---

## 1.2. Why synthpop-py?
The original **synthpop** package has become a widely used tool for generating synthetic tabular data. However, several practical limitations motivated the development of synthpop-py.

In particular we found that:
- the documentation differs from conventions commonly used in the Python scientific ecosystem;
- the package is difficult to integrate into larger software projects;
- the implementation is available only in R, while Python has become the dominant language for data science and machine learning;
- the software architecture makes maintenance and extension difficult;
- individual components are challenging to test and verify; and
- the implementation does not fully exploit modern computing resources.

synthpop-py addresses these limitations while preserving the sequential modelling approach introduced by synthpop. The primary goals of the project are to make synthetic data generation more accessible and easier to deploy in production environments.

More specifically, the package aims to provide:
- an accessible introduction to synthetic data generation through familiar Python APIs and comprehensive documentation;
- a modular and testable software architecture;
- reproducible synthesis workflows;
- improved scalability for larger datasets; and
- straightforward integration into existing Python data science workflows.

The current release focuses on providing a robust Python implementation of the synthpop methodology. While the R package currently contains a larger collection of synthesis methods and evaluation metrics, synthpop-py emphasises usability, reproducibility and maintainability.

---

## 1.3. When should you use this package?
synthpop-py is designed for generating **synthetic tabular data**.

Typical use cases include:
- sharing sensitive datasets with collaborators;
- developing and testing data analysis pipelines;
- teaching and demonstration purposes;
- exploratory data analysis; and
- evaluating statistical methods on realistic datasets.

The package supports datasets containing:
- floating-point variables;
- integer variables;
- boolean variables;
- string variables;
- categorical variables; and
- missing values.

The package is not intended for generating synthetic images, text, audio or other unstructured data.

##  1.4. Terminology
The terminology used in the synthetic data literature is not always consistent. Throughout this user guide we use the following definitions.

### 1.4.1. Original data
The **original data** is the dataset provided to the synthesiser. It contains the observations from which statistical relationships are learned. In the literature, this dataset is also commonly referred to as the **observed data**, **real data** or **source data**.

### 1.4.2. Synthetic data
**Synthetic data** is the dataset generated by the synthesiser. It aims to reproduce important statistical characteristics of the original data without reproducing the original records exactly. It is also referred to as **generated data** or **synthetically generated data**.

### 1.4.3. Synthesiser
The **synthesiser** is the central component of synthpop-py. It is responsible for fitting the synthesis models on the original data and generating synthetic observations. Other packages may refer to this component as a **generator**.

### 1.4.4. Utility
**Utility** described how useful a synthetic dataset is for analyses that would otherwise be performed on the original data. Literature distinguishes between utility and fidelity. In synthpop-py, the term utility is used broadly to describe how well the synthetic data preserves the statistical properties and relationships of the original data. A synthetic dataset with high utility should therefore support analyses that lead to conclusions similar to those obtained from the original data.

In the literature, this concept is also referred to as **analytical utility**, **data utility** or **fidelity**, depending on the context.

### 1.4.5. Privacy
**Privacy** refers to the extent to which information about individuals in the original dataset is protected after synthesis. Although synthetic data can reduce disclosure risks, generating synthetic data does not automatically guarantee privacy. Privacy should therefore be considered alongside utility when evaluating synthetic datasets.

### 1.4.6. Target
The **target** is the column currently being synthesised. Each synthesis method generates a single target column at a time.

### 1.4.7. Predictors
The **predictors** are the columns that have already been synthesised and are used as input to synthesise the target. By default, synthpop-py uses all previously synthesised columns as predictors. In the machine learning literature, predictors are also commonly referred to as **features**.
